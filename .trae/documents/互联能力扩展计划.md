# 梓安搞机工具箱 · 互联能力扩展计划

## Context（为什么做这个）

当前工具箱所有功能基于 USB ADB（截图/录屏/按键/应用管理/文件传输/脚本/终端）。用户要新增 4 个互联能力以达成「电脑 ↔ 手机跨端协作」体验：

1. **超级剪贴板**：电脑 ↔ 手机双向自动同步文字 / 图 / GIF
2. **文件同步**：列出图片/视频/音频/文档/手机存储分类，适配 vivo 办公套件，可传输任意文件
3. **屏幕镜像+控制**：scrcpy 弹出窗口，键鼠控制手机
4. **局域网直连**：剪贴板/文件同步/自动连接走纯局域网（HTTP over Wi-Fi），不走 `adb tcpip` 无线调试
5. **共存**：USB ADB 与局域网并列；USB 连接时同时启用两套；无线调试继续承担现有功能（含 scrcpy）
6. **自动连接 ≤30s，应用层吞吐 ≥100Mbps**
7. **完成后精简代码**

手机端必须装一个常驻 APK（`com.zian.bridge`）充当 HTTP/UDP 服务端。本机无 JDK 无 Android SDK，需先装 JDK 17 + Android cmdline-tools + build-tools 34 + platform 34。

- ADB 通道（USB/无线调试）：截图、录屏、按键、应用管理、scrcpy 镜像、ADB 终端、文件 push/pull（保留）

### 2.3 关键模块

**BridgeApp.java**（必须，规避 NanoHTTPD 上传陷阱）
```java
public class BridgeApp extends Application {
  @Override public void onCreate() {
    super.onCreate();
    // NanoHTTPD 默认写到 /data/local/tmp，普通应用无权限，上传 >1MB 会 500
    System.setProperty("java.io.tmpdir", getCacheDir().getAbsolutePath());
  }
}
```

**BridgeService.java**（前台服务）
- `onStartCommand`：启动通知（Android 13+ POST_NOTIFICATIONS）→ 启动 HttpServer + ClipboardWatcher + MdnsBroadcaster
- `onDestroy`：三者逆序 stop
- `foregroundServiceType=ForegroundService.Type.DATA_SYNC`（Android 14+ 必需）

**HttpServer.java**（NanoHTTPD 端口 35791）
路由表：
| 路由 | 用途 |
|---|---|
| GET /ping | 返回 `{name, model, android, ver, ip}` |
| GET /clipboard | 返回 `{type:'text'\|'image', data: base64或text, sig}` |
| POST /clipboard | body=plain text 或 multipart image，写入 ClipboardManager |
| GET /files?type=images\|videos\|music\|docs\|all&dir= | MediaStore 列表 JSON |
| GET /file?path= | 流式下载，`newFixedLengthResponse` + 1MB BufferedInputStream |
| POST /file?path= | `session.parseBody(files)` + `FileChannel.transferTo` 零拷贝 |
| GET /open?path=&app=vivo_office | `Intent` 跳 com.yozo.vivo.office |
| GET /vibrate?ms= | 触觉反馈（小特性，可省） |

文件流式下载模式（关键代码，提速 ≥100Mbps）：
```java
File f = new File(path);
FileInputStream fis = new FileInputStream(f);
BufferedInputStream bis = new BufferedInputStream(fis, 1 << 20);   // 1MB buffer
Response res = newFixedLengthResponse(Status.OK, getMimeTypeForFile(path), bis, f.length());
// NanoHTTPD 内部 BUFFER_SIZE=16KB 默认；反射调大或重写 serve() 直接管道写
res.addHeader("Content-Disposition", "attachment; filename=\"" + f.getName() + "\"");
res.addHeader("Connection", "keep-alive");
return res;
```

上传接收模式：
```java
Map<String, String> files = new HashMap<>();
session.parseBody(files);                  // 已流式落盘到 getCacheDir()
String tmp = files.get("file");
try (FileChannel in = new FileInputStream(tmp).getChannel();
     FileChannel out = new FileOutputStream(target).getChannel()) {
  in.transferTo(0, in.size(), out);         // 零拷贝
}
```

**ClipboardWatcher.java**（防回环）
- 注册 `ClipboardManager.OnPrimaryClipChangedListener`
- 维护 `localSig`（本地剪贴板指纹），变化时记录
- 接收 `/clipboard` 写入时设置 `echoGuard=sig`，监听器回调若 sig==echoGuard 则忽略

**MdnsBroadcaster.java**（不用 NsdManager，用 UDP 多播）
- `MulticastSocket(35791)` 加入 `239.0.0.1`
- 每 5 秒广播 JSON `{name:'vivo X100 Pro', model:'V2324A', android:'16', ver:'1.0', port:35791}`
- Android 7+ 上 NsdManager 在前台服务外不稳定，多播反而可靠

**FileHelper.java**（MediaStore）
- 图片：`MediaStore.Images.Media.EXTERNAL_CONTENT_URI`
- 视频：`MediaStore.Video.Media.EXTERNAL_CONTENT_URI`
- 音频：`MediaStore.Audio.Media.EXTERNAL_CONTENT_URI`
- 文档：扫描 `Environment.DIRECTORY_DOCUMENTS` + `Environment.DIRECTORY_DOWNLOADS`，按扩展名 .doc/.docx/.xls/.xlsx/.ppt/.pdf/.txt 过滤
- 手机存储：`/sdcard/` 目录树（用户授权 MANAGE_EXTERNAL_STORAGE 时支持，否则只列公共目录）

**VivoOfficeAdapter.java**
```java
Intent i = new Intent(Intent.ACTION_VIEW);
i.setPackage("com.yozo.vivo.office");   // 永中 Office vivo 版
i.setDataAndType(uri, mimeType);        // .doc → application/msword 等

```

### 2.4 build.ps1 编译脚本
```powershell
$ErrorActionPreference='Stop'
$JAVA='C:\Java\jdk17\bin'
$BT='C:\Android\sdk\build-tools\34\34.0.0'
$PL='C:\Android\sdk\platforms\android-34\android.jar'
$SRV='apk-src'

# 1. 编译资源
& "$BT\aapt2.exe" compile --dir $SRV\res -o compiled.zip
& "$BT\aapt2.exe" link -o app-unsigned.apk -I $PL --manifest $SRV\AndroidManifest.xml `
    -R compiled.zip --java src/com/zian/bridge/R.java

# 2. 编译 Java（含 R.java）
& "$JAVA\javac.exe" -classpath "$PL;$SRV\libs\nanohttpd-2.3.1.jar" `
    -d classes $SRV\src\com\zian\bridge\*.java $SRV\src\com\zian\bridge\R.java

# 3. d8 转 dex
& "$BT\d8.bat" --output dex/classes.dex classes\com\zian\bridge\*.class

# 4. 把 dex 加入 APK
Copy-Item app-unsigned.apk app-tmp.apk
Add-Type -AssemblyName System.IO.Compression.FileSystem
$zip=[System.IO.Compression.ZipFile]::Open((Resolve-Path app-tmp.apk),'Update')
$zip.GetEntry('classes.dex') | ForEach-Object { $_.Delete() }
$zip.CreateEntryFromFile('dex\classes.dex','classes.dex') | Out-Null
$zip.Dispose()

# 5. 对齐 + 签名
& "$BT\zipalign.exe" -f -v 4 app-tmp.apk app-aligned.apk
& "$BT\apksigner.bat" sign --ks debug.keystore --ks-pass pass:android `
    --out app.apk app-aligned.apk

Write-Host '✅ app.apk 已生成'
```
debug.keystore 用 `keytool -genkeypair -keystore debug.keystore -keyalg RSA -keysize 2048 -validity 10000 -alias androiddebugkey -storepass android -keypass android -dname "CN=Android Debug,O=Android,C=US"` 一次性生成。

## 四、自动连接与速率保证

### 4.1 自动连接（≤30s）
- 电脑端启动时（main.js `app.whenReady` 后）异步触发 `net:scan(30000)`
- 找到的设备写入 `BASE_DIR/links.json` 缓存
- 下次启动先尝试连接缓存中的设备，3 秒握手失败再走全量扫描

### 4.2 速率保证（≥100Mbps ≈ 12MB/s）
- NanoHTTPD 端：1MB BufferedInputStream + FileChannel.transferTo 零拷贝上传
- Node.js 端：`http.get` 后 `response.pipe(fs.createWriteStream)`，HTTP keep-alive
- TCP 缓冲：socket.setNoDelay(true) + setKeepAlive(true, 30000)
- 大文件分块 1MB，小文件直接传输
- Wi-Fi 6 路由器 5GHz 频段实测可达 300Mbps，2.4GHz 仅 50Mbps（用户需保证 Wi-Fi 5G）

   - 同时插入 USB + 同 Wi-Fi → 下拉两个设备都显示，剪贴板走 Wi-Fi，scrcpy 走 USB
10. **稳定性**：
    - 拔 USB → scrcpy 进程退出；局域网设备不受影响
    - 关 Wi-Fi → 局域网设备消失；USB 不受影响
    - 退出程序后无残留进程
